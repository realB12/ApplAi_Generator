The following AI configuration files are required by the Kimi (Vibe-)Code Generator to know what and how to build stuff to meet our requirements in terms of features (SPEC.md) and [scaffolding](../../../../../../../../../WORK/ENTITY/AI/SETUP/Scaffolding/AI_Scaffolding.md) (TECH.md). 

The sum of those files represent the highlevel specs for the such generated Application prototype and will remain relevant to represent the core principles upon what the app is built.

><span style="color:red; font-weight:bold">**ACHTUNG</span>: so you better some time to get those files right and you fully understand their meaning before prompting for the first time.**

Find the documented Templates in the [KIMI Service Description](../../../../../../../../../../WORK/ENTITY/AI/PROVIDER/K/Kimi/CONFIG/KIMI%20Project%20Configuration%20Files.md)

## List of Configuration Files

```plaintext
AI.KIMI/CONFIG
│ 
├── VISION.md         * Persistent purpose and core product idea
├── SPEC.md           * Screens, GUI-components, navigation, functionality
├── TECH.md           * Scaffolding: Platform, Devices, IDE, DBs, Language, ... 
├── BOUNDARIES.md     * Controlling agentic systems
├── PATTERNS.md       * Enforcing rules on code level
├── CHANGELOG.md      * What has been done/changed, versioning
├── SESSION.md        * Keeping track of the prompts
└── DECISIONS.md      * Logging the Why
```

**The most important files are SPEC and TECH** which together define the Vibcode and the Platform where and how its executed. All other files, such as README and VISION are summaries, derived from them or just historical or operational (such as CHANGELOG, SESSION, DECISIONS) 

## How to use those configuration files
Rather than editing or loading them manually into the AI, we provide them in the app's GitHub Repo the AI prompt simply can refer to. 

## How those Context files are created
All those files are either created by the AI upon telling the AI what we are going to build and to generate the full set of context files it needs for vibcoding or they are derived from ready made [Template](../../../../../../../../../WORK/ENTITY/AI/PROVIDER/K/Kimi/CONFIG/TEMPLATES/SPEC_template.md) which then will be AI checked again to make sure they are up-to date in terms of technolgy and best practices. 

-> find more details in the [KIMI Configuration Templates Folder](../../../../../../../../../WORK/ENTITY/AI/PROVIDER/K/Kimi/CONFIG/TEMPLATES/_KIMI%20Configuration%20Templates.md)

## Files Overview

* **VISION.md**: The **Why** — The **Product Vision**, target audience, success criteria. Updates only when product direction changes

* **SPEC.md**: The **What** — **Functional Specification**: screens, features, user stories, acceptance criteria, edge cases. This is the files that changes on every new feature or further specifications on details when the projece evolves.  

* **TECH.md**: The **How** — **[Scaffolding](../../../../../SETUP/Scaffolding/AI_Scaffolding.md)** the project: Tech-stack, architecture, data model, API contracts, decisions. This file is normally generated by the AI when asked to build it upon a first draft Vision and Specs with some initial, minimal architectural preferences.  

* **BOUNDARIES.md**: The **Don't** — constraints, forbidden patterns, scope limits. Even more than the TECH.md, the Boundaries should be generated by the AI. It's more some kind of AI internally generated lookup documentation than a specification in your behalf. 

* **PATTERNS.md**: The **Template** — reusable code patterns, conventions that are normally compiled by the AI. Again, more an AI internal work-document than something you should manually modify. 

* **DECISIONS.md**: The **Architectural WHY** — explaining key choices made for historical reasons. Has normally no impact on the generated code. More or less just documenting your (non binding) decisions (which might not be followed by the actual code). 

* **SESSION.md**: The "Now" — current work, blockers, next steps: will be updated by the AI after every session. Great for you to look up where we are in the building process but nothing you should mingle with yourself.
